# 分镜资产生成节点设计（2026-10-21）

用户已选择直接扩展现有 H3 分镜文本生成器，并授权以未发布的资产契约重新设计；另需可独立用于外部LLM的系统指令。

## 唯一真相与边界

- 新资产 version=2：角色列表、镜头选项、有序动作/对白事件、目标时长与续接重叠帧。资产不保存另一份可漂移的完整H3提示词。
- 用户输入用角色标记，如“角色2动作：递出苹果”“角色2：吃苹果吗？”。角色设置提供名称、画面内/画外、位置和声音要求。台词与动作原文、角色归属和事件顺序是锁定数据。
- LLM负责分镜分组、片段时长和英文执行稿；代码对角色编号、事件逐条等价、镜头数量、出镜名单和选项进行校验。用户的中文要求保留在原始字段中，执行稿以正向可见状态表达限制：例如“角色1不接苹果”编译为“角色2是唯一持有者，角色1双手可见且空着”。英文动作按事件ID绑定并要求以对应执行者开头；`execution.visible_state` 与动作指令拒绝否定控制词。不符合时最多两次纠正重试，仍失败不输出不完整资产。
- V3确定性编译结构化事件；不在组装时重新调用LLM或改写动作/对白。允许纯动作镜头，去掉旧资产的两句一镜、必须接场景/声音的限制。
- 首轮真实渲染暴露中文导演约束被念出、苹果所有权失效，详见 docs/qa/storyboard-generation-20261021/initial-render-failure.md。第二轮虽修正语言，男猫仍在后段接到复制出的苹果，说明逐字翻译否定限制仍不可靠。最终契约将原文与 execution 分离：H3 非对白内容仅使用英文，并以 `visible_state` 描述画面中应该持续成立的物理状态。不能以结构通过代替成片验收。
- 目标时长按24fps、17*k+5网格分配；续接重叠帧显式记录并与Loop配置匹配。默认22帧，输出展示实际预计交付时长。
- 不改变发布的V2视频生成轨道；旧资产读取代码可以留存作内部验证，生成入口不提供旧格式兼容模式。

## 节点与外部生成

现有生成器增加明确角色数量、角色设置、目标时长、续接重叠、镜头景别/机位/视角及导演约束；保留可读分镜预览，同时直接输出MIE_STORYBOARD与完整资产JSON。既有文本输出可作为新结构的派生视图，不作为另一套生成管线。

系统指令、JSON契约、节点LLM调用使用同一份资源；外部LLM生成的同格式JSON经过同一校验器后可Save/Load/V3。提供完整可复制提示词、输入模板和两个例子，不要求外部环境调用本机工具。

## 验证

- 刺猬/板栗：两名角色在沙发对话；提及刺猬只属于对白，不擅自新增动物、回忆镜头或暴力动作。
- 吃苹果吗：两角色，两镜七句；角色2持有并递苹果，角色1拒绝，不接过或咬苹果，不新增和解。
- 单元测试锁用户原文、人物与图片/声音编号分离、事件顺序、动作角色、选项、帧网格、纯动作和画外音。
- 每例多seed真实LLM输出经同一校验，再入库并用V3编译；按参考成片配置实际渲染并检查出镜、动作归属、对白覆盖与顺序。
- 当前已验证的单图POV authored样本作为回归，不因新生成入口退化。
