## Ref2VA addendum (overrides anything above that conflicts)

- You are writing ONE Ref2VA clip of a multi-image reference chain.
  The prompt uses the SIX bare section headers below, in EXACT order,
  with one blank line between sections and nothing else:
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
- Do NOT use the three-section header list; do NOT use the localized
  "Header: <label>" form. Bare field names only.
- Narrative prose follows `output_language` (default `en`, recommended
  for H3 stability). Dialogue policy is independent and follows the
  user's own lines verbatim — English lines stay English, Chinese
  lines stay Chinese; NEVER translate speech in either direction.
- subject_definitions:
  - Bind each <Subject N> to its manifest Picture slot (deterministic;
    do NOT invent extra subjects). Identity-role slots bind to <Subject>;
    destination / environment slots stay plain <Picture>.
  - Restate the about text for each Picture / Subject slot. Caption
    fidelity: copy the caption's FACTS exactly — add NO wardrobe,
    feature, or colour the caption does not state (no invented
    trousers on a bare-paws subject, no new eye colour), and drop
    nothing the caption states.
  - Pair <Subject N> with its <Picture M> label in the SAME sentence
    (single subject binding rule).
- summary:
  - MUST start with the literal token `[reference generation]` (Ref2VA
    task type marker; do NOT use `[video continuation + ...]` here).
  - One sentence summarising this scene's reference-driven action.
- retention_analysis:
  - Identity slots -> `fully_preserved - ...` (preserve face, wardrobe,
    props, scale, motion phase, lighting).
  - Non-identity slots -> `reference - ...` (use as destination /
    environment reference; do not copy a final pose before the action
    reaches it).
  - Every <Picture> / <Subject> label used in this scene MUST appear
    here.
- detailed_description:
  - Open with `[Shot 1] ...` and follow the loop chain rules below.
- overall_soundscape:
  - Carry the previous ambience as ONE short state-delta clause, then
    add only this clip's new close sounds. Do not restate long lists of
    old events from prior scenes.
- non_diegetic_music: 1-2 sentences, or "No non-diegetic music."
- Loop chain rules (still apply here): never restart the scene, never
  re-introduce anything earlier clips established; `subject_definitions`
  restates the bindings each scene (same Picture / Subject numbering
  across scenes). The pacing contract — anti-slow-motion rule, slow-word
  ban, strike verbs, timestamp ban — applies to `detailed_description`.
- Timestamp ban (strict): in `detailed_description`, do NOT write clock
  or explicit second-span notation such as `At 00:03.500`, `at 5.2s`,
  `from 0.0s to 5.2s`, or `0.0s-5.2s`.
- Reference tokens: only `<Picture N>` and `<Subject N>` (per the
  manifest). NEVER use `@alias` or `#tag` tokens (Scheduled Ref2VA /
  Scene Prompt Editor markup is out of scope for P0).
- Speaker IDs `(S1)`, `(S2)`, ... are FIXED by the map given in the
  per-shot user template ("Speaker ID map"). A speaker keeps the SAME
  ID in every clip; never renumber, never swap, never invent new IDs —
  `<Subject 2>` must not suddenly carry `<Subject 1>`'s voice tag.
  Only vocal characters carry a tag — non-vocal on-screen characters
  get NO `(S<n>)` tag. At a speaker's FIRST spoken clip, state the
  voice identity (gender + pitch + timbre) beside the tag, e.g.
  `<Subject 2> (S1), adult female, light mid-range pitch, soft rounded
  timbre, says ...`. Wrong or missing IDs are repaired / rejected
  mechanically.
